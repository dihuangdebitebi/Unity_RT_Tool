# Unity 实时翻译工具（Unity 实时翻译器）

昴娘个人独立开发 · 完全免费开源

一个 **Unity 游戏**实时翻译工具（如 The Lewd Knight）。启动游戏时自动部署翻译插件，把游戏画面里显示的**英文/日文 实时替换成中文**。

**完全离线运行**：翻译模型就在 `models\` 文件夹里，不需要联网，不需要安装任何环境。
**即点即翻**：切到哪里翻哪里，不用整包翻译游戏。
**自动部署**：没装插件也能玩——工具自带 BepInEx + XUnity.AutoTranslator，自动帮你装好。

---

## 使用方法（三步）

1. **双击** 打开工具窗口。`Unity_RT_Tool.exe`
2. **选游戏**（任选一种方式）：
   - 点「**自动查找**」—— 工具会在 `E:\GAME` 和常见 `game\` 文件夹自动找
   - 点「**选择游戏exe…**」—— 直接选游戏的 `.exe`（如 `The Lewd Knight.exe`）
   - 点「**选择游戏文件夹…**」—— 选整个游戏目录
3. 点「▶ **启动游戏并开始实时翻译**」→ 工具自动部署插件并启动游戏 → **游戏一加载，画面上的英文/日文就开始变成中文**，一直在线，直到你点「■ 停止翻译」。

> 选 exe 或文件夹后，工具会自动读取游戏**插件真正使用的那份**配置里的端口（默认 5000），一般不用手动改。

**日文/英文都能翻**：在「选项」里选翻译方向，默认是 **自动（英文 + 日文 混合）**：
- **自动（英文 + 日文 混合）** —— **逐句识别**原文是英文还是日文，英文、日文、英日混排都能翻（**推荐，绝大多数游戏选这个就行**）
- **仅英文 → 中文** —— 确定游戏文本全是英文时才选
- **仅日文 → 中文** —— 确定游戏文本全是日文时才选

> v1.3 起用「自动」即可。以前只有英文/日文二选一，选错了、或游戏里两种语言混着出现，
> 就会出现「一部分翻得了、一部分翻不了」。

## 文件说明

| 文件/文件夹 | 说明 |
|---|---|
| `Unity_RT_Tool.exe` | 主程序（双击运行） |
| `_internal\` | 程序运行库，别删、别动 |
| `embedded_plugins\` | 内置的翻译插件（BepInEx + XUnity.AutoTranslator），给没装插件的游戏自动部署用，别删 |
| `models\qwen2.5-1.5b-instruct-q4_k_m.gguf` | 离线翻译模型（约 1GB），整个工具离线就靠它，别删 |
| `cache_mt.pkl` | 机翻缓存（首次运行后自动生成，可删） |
| `config.json` | 你的上次设置（端口、游戏路径等），可删 |

## 常见问题

**Q：打开后软件闪退 / 什么都没翻译？**

先看文件夹里有没有生成 `crash_dump.txt`（闪退时会写这里）——把内容发给开发者即可定位。

1. **杀毒软件/360 误拦截**比较常见：把 `Unity_RT_Tool.exe` 加入白名单/信任，且把 `models\`、`_internal\` 也加信任。
2. **游戏没装插件**：工具会自动检查（看 `BepInEx\plugins\` 或 `AutoTranslator\` 里有没有 XUnity 插件本体）。没装的话会弹窗问你是否**自动部署**内置插件——点「是」即可。装好后游戏里英文就能实时翻译了。
3. **端口被占**：默认 5000。如果被占，改「服务端口」为其他数（如 5001），工具会同步把它写进游戏那份**正确的**配置文件。
4. **机器内存太低**：模型加载约占 1GB。模型是点翻译前才加载的，加载不出来会直接弹窗提示，不会悄悄闪退。

**进阶自检（命令行）：**
```
.\Unity_RT_Tool.exe --selftest      # 验证模型能加载+翻译，写 selftest.log
```

**Q：游戏装了翻译插件，却一个字都不翻译？**

Unity 的 XUnity.AutoTranslator 插件有**两种装法，配置文件不是同一个名字**：

| 装法 | 插件真正读取的配置 |
|---|---|
| BepInEx 系（根目录有 `BepInEx\`、`winhttp.dll`） | `BepInEx\config\AutoTranslatorConfig.ini` |
| ReiPatcher 系（有 `ReiPatcher\`，或 `_Data\Managed\` 里有 `XUnity*.dll`） | `AutoTranslator\Config.ini` |

所以有两种翻不了的情况，工具都能自动处理：

1. **翻译源是空的**——汉化/重打包游戏常见：`[Service] Endpoint=`、`[Custom] Url=` 都没值，
   插件在跑却没人可问。
2. **改错了文件**（BepInEx 系，v1.3.1 修复）——插件根本不读 `AutoTranslator\Config.ini`，
   于是它一直用内置默认值（**连在线谷歌翻译 + 目标语言英文**），断网就每一条都失败，
   界面上一个汉字都不变。

v1.3.1 起，工具会在启动前**自动判断插件的装法**，只改**它真正会读的那一份**，
并补上 `Endpoint=CustomTranslate`、`Language=zh`、`FromLanguage=auto`、`Custom\Url`。
改动前先把原文件备份成 `*.bak.日期时间`，且**不会删、不会改** `Translation\` 里你已有的任何翻译文件
（例如其它汉化工具生成的 `_RenpyThiefTranslations.txt` 原样保留）。

> 线索：如果游戏目录里出现了 `Translation\en\Text\`，说明目标语言没被设成中文。

**Q：翻译出来了，但显示成一堆方块 □？**

这**不是翻译失败**，是**字体缺字形**。工具只换文字内容，渲染用的还是游戏自己的字体：

- 日文游戏的日文字体（如 `ipaexm`）只有日文字集 → 没有「邮 / 击 / 钮 / 继 / 续」这类**简体专有字**；
- 有些界面用纯拉丁字体（如 `Oswald` / `LiberationSans`）→ **一个汉字都没有**。

v1.3.2 起，工具**自带一套黑体中文字体**（Noto Sans SC / ARIALUNI，OFL 许可），启动游戏时会把它
放进游戏目录并设为 TextMeshPro 的**后备字体**（缺字形时才用它兜底，保留游戏原本字体外观）。
这样**本身不带中文字体的游戏也能直接翻**。工具**不会**覆盖游戏 / 汉化包已配好的字体设置。

> 极少数游戏的自定义材质不吃后备字体：把游戏配置里
> `FallbackFontTextMeshPro=...` 的键名改成 `OverrideFontTextMeshPro=`（值不动）即可强制覆盖。
> 配置位置：BepInEx 装法在 `BepInEx\config\AutoTranslatorConfig.ini`，ReiPatcher 装法在 `AutoTranslator\Config.ini`。

**Q：名字翻好了，但技能 / 物品的大段介绍还是原文？**

插件默认有一个长度上限 `MaxCharactersPerTranslation=200`，含义是
**"超过 200 个字符的文本，整条不翻译"**（不是截断，是直接跳过）。
游戏里名字只有几个字、介绍动辄 90~480 字符，所以名字能翻、正文全被跳过。

**v1.3.3 起**工具会把上限提到允许的最大值 **2500**，并且：

- **长文本分段翻译**：按原文的换行 / 句末切成小段逐段翻，再原样拼回 ——
  译文完整，**原文的换行排版也保留**；
- **强化翻译指令**：逐句完整翻译，禁止概括和删减。

> 长文本第一次出现要等几秒到十几秒（本地模型在算），**同一句第二次出现秒出**。

**Q：翻译质量怎么样？**

用的是 Qwen2.5-1.5B 离线翻译模型，看懂剧情完全够用，个别句子会生硬。翻译结果会缓存到 `cache_mt.pkl`，同一句话下次秒出。

**Q：会不会改坏游戏文件？**

不会。游戏文件只读，翻译是外挂式实时替换画面文字，游戏原始文件不动。工具只会往游戏目录
**新增**插件（`AutoTranslator\`），并在需要时按上一问的方式修正其中的配置（含备份）。

**Q：游戏里有时显示原文有时显示中文？**

翻译是"看到了才翻"，首次出现有 1~2 秒延迟，翻译过的句子（已缓存）秒出。短单词（如 `NO`、`YES`）默认不翻。翻译方向保持默认的 **「自动（英文 + 日文 混合）」** 即可，不用再手动猜语言。

**Q：支持所有 Unity 游戏吗？**

支持标准 Unity + Mono 的游戏。没装插件的会自动帮你部署。注意：只有用标准 UGUI / TextMeshPro / NGUI 绘制文字的游戏能实时翻译；用自定义渲染（文本画在图片里的）、IL2CPP 加密较深的游戏可能无法翻译。
